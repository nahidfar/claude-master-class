Put your full app online with Vercel

GitHub Pages shows your public portfolio. Vercel runs the whole app: your portfolio, your login and all three AI tools, on a link you can open from anywhere. It takes about 15 minutes, and the Hobby plan is free for personal projects.

Numbered yellow boxes on each screenshot show where to click, in order. The covered labels are placeholders: you'll see your own GitHub username, repository name and Vercel account there.

Before you start

  • Your app works on your laptop, including login and the three tools.
  • Your code is pushed to your own GitHub repository, on the main branch.
  • main has the full app, not the static GitHub Pages copy. Vercel needs normal Next.js output, so next.config.ts on main must not contain output: "export".
  • Your .env.local file is open in VS Code. You'll copy its settings into Vercel.
1

Create your Vercel account

  1. Go to vercel.com/signup and choose the Hobby plan (free, for personal projects).
  2. Choose Continue with GitHub. This is the easiest option: your Vercel account and GitHub are connected in one go.
  3. Prefer email or Google? That works too. You'll connect GitHub in step 3.
2

Start a new project

On your Vercel dashboard, click 1 Add New (top right), then 2 Project.

3

Connect GitHub

Under Import Git Repository, click 1 GitHub and approve the sign-in in the window that opens.

Signed up with GitHub in step 1? You may skip this screen and go straight to a list of repositories.

4

Let Vercel see your portfolio repository

If your portfolio repository already shows in the list, skip to step 5. If it doesn't, Vercel doesn't have access to it yet:

  1. Open 1 the dropdown showing your GitHub username and click 2 Add GitHub Scope.
  2. GitHub opens. Choose your GitHub account.
  3. Under Repository access, choose 1 Only select repositories, open 2 Select repositories and pick your portfolio repository.
  4. Click 3 Save (or Install) and return to the Vercel tab.

Why "Only select repositories"? Vercel then sees only the repository you want to publish, not everything in your GitHub account.

5

Import your repository

Find your portfolio repository in the list (use Search if you have many) and click 1 Import.

6

Check the project settings

7

Add your environment variables

Your app reads its password, session secret and AI key from settings called environment variables. On your laptop they live in .env.local, which never goes to GitHub. Vercel needs its own copy. Open Environment Variables on the same screen.

⚠️ Check first: your list may be different

The table below is what the class app uses. If you or your coding assistant changed the app after class, it may need different or extra settings. Before you add anything, paste this into your coding assistant:

I'm deploying this app to Vercel. Read .env.example and the code,
and list every environment variable the app needs in production.
Mark each one required or optional and say what it is for.
Show names only. Never print the values from my .env.local.

The settings the class app uses:

KeyValue
SITE_PASSWORDThe password for your private toolsRequired
SESSION_SECRETLong random text, 32+ charactersRequired
AI_PROVIDERopenai, anthropic, gemini or openai-compatibleRequired
AI_MODELYour model nameRequired
AI_API_KEYYour AI keyRequired
AI_BASE_URLOnly for openai-compatibleOptional
AI_REASONING_EFFORTlow, medium or highOptional

The fastest way to add them:

  • Paste: open .env.local in VS Code, select everything, copy, and paste it into the 1 first Key box. Vercel splits it into separate variables.
  • Or import the file: click 2 Import .env and choose .env.local. On a Mac the file is hidden; press Cmd+Shift+. in the file picker to show it.
  • Or one at a time: type each Key and Value, and click Add More for the next.

Leave Environments as Production and Preview. Check that every key from the table is there and has a value.

Keep these private

These values are your password and your paid AI key. Paste them only into Vercel, never into chat, email or a GitHub file. Anyone with your link can see your portfolio, but only someone with SITE_PASSWORD can use your AI tools and spend your credit.

Forgot one? You can add or change variables after deploying: open your project → Settings → Environment Variables. A change only takes effect after a new deployment: go to Deployments, open the ⋯ menu on the latest one and choose Redeploy.

8

Deploy

  1. Click 3 Deploy at the bottom of the same screen. Vercel installs your app and builds it, the same as npm run build on your laptop. This takes one to three minutes.
  2. When it finishes, Vercel shows a preview of your live site.
  3. Open your project's dashboard. It shows your live link under Domains, plus the latest deployment and its status.
9

Test your live app

  1. Open your .vercel.app link. Your portfolio loads for anyone.
  2. Open /dashboard in a private window. It should send you to the login page.
  3. Log in with your SITE_PASSWORD.
  4. Run each tool once with a real job description: Job Fit, Cover Letter, Interview Prep / Study Plan.

Done

Share the link in applications and on LinkedIn. Your private tools stay behind your password.

10

How updates work

  • Every time you commit and push to main, Vercel rebuilds and updates your live site automatically, usually within a few minutes.
  • Push to any other branch and Vercel builds a separate preview link, so you can check a change before it goes live.
  • Each update shows on the Deployments tab with its status: Building, Ready or Error.

A quick way to ship a change: ask your coding assistant to "commit my changes with a clear message and push to main", then watch the Deployments tab.

If something breaks

You seeWhat to do
Build failedOpen the failed deployment → Build Logs. Copy the whole error into your coding assistant and ask it to fix the cause, then push again.
Your repository isn't in the import listRepeat step 4 and add the repository to Vercel's access on GitHub.
"Missing" setting or a 503 errorA variable is missing or misspelled. Fix it under Settings → Environment Variables, then Redeploy.
You changed a variable but nothing changedVariables apply only to new deployments. Redeploy the latest one.
Build fails with an "export" error, or login and tools are missingnext.config.ts on main has output: "export". Remove it from main; keep it only on your GitHub Pages copy.
A tool says the AI provider is rate limited or out of creditAdd credit or wait a minute. Check the key in AI_API_KEY is the one with credit.
A tool takes very longReasoning models can take a minute or two. Set AI_REASONING_EFFORT to low and redeploy.
